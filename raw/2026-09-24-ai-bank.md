## Context window

**Past half the context window the agent gets dumber, and compaction silently drops details.**

- For heavy work (CLIs, browsers) **stay under half**, two-thirds at most.
- Long build-fix loops: **choose the [1M window](https://platform.claude.com/docs/en/build-with-claude/context-windows#context-window-sizes-by-model)**; 400k runs out.
- Every turn [resends the whole conversation](https://platform.claude.com/docs/en/build-with-claude/context-windows#how-the-context-window-works): a **cold resume reprocesses everything**. ⚓ *"hi" = 500 credits, again*
- [Cache](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) lives about an hour: before breaks, **[`/compact`](https://code.claude.com/docs/en/commands) or write a handover**.
- **New task, new session**, unless same files. ⚓ *dragging your traumas along*
- **Never let it auto-compact**: hitting the limit means you oversized the task.
  - back plus front across two systems: 1M
  - a validation rule: 200k
- **Scout sub-agents** → *Specialist subagents*, for:
  - legacy code
  - [Confluence](https://github.com/victorrentea/petclinic/blob/main/.claude/skills/confluence-cli/confluence.py)
  - the internet

## Grilling the plan

**Plan mode asks 3-5 questions; a grill-me prompt asks 10+, one at a time, each with a recommended answer.**

- **Branch pruning** of the decision tree, starting with the most pivotal question. ⚓ *back vs front paging*

  - a recommended answer, for when your brain goes flat
  - one question at a time
  - looks facts up itself, decisions stay yours
- Append "**functional questions first**, for a non-technical PO" to split business from engineers.
- Run it in [plan mode](https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode), **never autopilot**: it stops asking.
- **Critical facts it missed** (100k owners) go into [AGENTS.md](https://github.com/victorrentea/petclinic/blob/main/AGENTS.md): agentic engineering is parenting.
- **Approach it with humility.** ⚓ *Victor, Spring trainer, didn't know about [Page](https://docs.spring.io/spring-data/commons/reference/repositories/query-methods-details.html)*

**Humans read the code only after other LLMs reviewed it and the author confessed its doubts.**

- **One LLM writes, others review**: [`/code-review`](https://code.claude.com/docs/en/commands) 🚧 fires four subagents on the diff. ⚓ *≈$7 on top of $20*
- Then **ask the author where it hesitated**, like you'd ask a human. ⚓ *"0.5% sure about this"*
- Better: tell it upfront to **log its assumptions in a markdown** as it goes.
- The **escalation report** lists:
  - places it was uncertain
  - reviewer findings it refused to fix
  - fixes that might overfit

## 🎯 Main takeaways

- Any MCP job a terminal CLI can do too — MCP only pays off for cloud agents.
- Pay for intelligence where a wrong turn is costly, not for bulk reading.
- AGENTS.md is the most important file in your git: preloaded in every chat, it spares project rediscovery.
- Every time the AI annoys you, take revenge by teaching it one more line of context.
- Never reproduce a bug by hand: the agent drives a browser from the terminal and proves the fix.
- Plan mode asks 3-5 questions; a grill-me prompt asks 10+, one at a time, each with a recommended answer.
- You stay accountable for AI code, so learn the fundamentals the hard way first.
